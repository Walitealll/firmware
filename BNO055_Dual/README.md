# BNO055 Dual для STM32CubeIDE

Отдельный проект для платы STM32F103C8Tx. Только I2C и два BNO055, без BLE,
ЭМГ и USB. Основная прошивка хранится отдельно. Запуск Debug загрузит
диагностическую прошивку в ту же плату.

## Запуск

1. Завершите старую сессию Debug. В CubeIDE выберите **File → Import →
   General → Existing Projects into Workspace**. В **Select root directory**
   укажите каталог `BNO055_Dual`. Если импортируете ZIP, выберите
   **Select archive file** и укажите `BNO055_Dual_CubeIDE.zip`.
2. Отметьте `BNO055_Dual` и нажмите **Finish**. Затем выберите проект и
   нажмите **Project → Build Project**. Сборка штатная для CubeIDE и создаёт
   `Debug/BNO055_Dual.elf`. Пути к инструментам и PowerShell настраивать не нужно.
3. Откройте **Run → Debug Configurations → STM32 C/C++ Application →
   BNO055_Dual Debug** и нажмите **Debug**. После остановки в `main`
   нажмите **F8 (Resume)**.
4. В **Live Expressions** добавьте три выражения: `g_bno_internal`,
   `g_bno_external` и `g_bno_pair`. Для углов выберите формат **Natural**.

## Что смотреть

| Поле | Как читать |
| --- | --- |
| `init_result` | `BNO_INIT_OK` (1) — датчик запущен. I2C1 и I2C2 проверяются независимо. |
| `opr_mode`, `sys_status`, `sys_err` | Младшие четыре бита режима должны быть `0xC` (NDOF), статус `5`, ошибка `0`. |
| `sample_ok`, `sampled_ms`, `io_errors` | Успех последнего чтения, время последнего успешного чтения и счётчик ошибок. |
| `euler_deg`, `quaternion` | Углы в градусах и кватернион BNO055. Углы доступны для диагностики и до привязки к северу. |
| `calib.sys`, `calib.gyro`, `calib.accel`, `calib.mag` | Уровни калибровки 0–3; `fully_calibrated` означает 3 по всем четырём полям. |
| `crystal_requested`, `crystal_active`, `clock_fallback` | Запрошенный кварц, прочитанный выбор генератора и факт переключения на внутренний генератор. |
| `accel_ms2`, `accel_norm_ms2`, `gyro_dps`, `mag_ut` | Ускорение (м/с²), его модуль, угловая скорость (°/с) и магнитное поле (мкТл). В покое модуль ускорения должен быть около 9,8 м/с². |
| `g_bno_pair.north_ready` | Оба датчика читаются в NDOF и оба имеют `calib.sys > 0`. |
| `g_bno_pair.reported_heading_delta_deg` | Разница курсов на выходе двух BNO055 (внешний минус внутренний) с учётом перехода 359° → 0°. Доступна при работающем NDOF даже с `calib.sys = 0`. |
| `g_bno_pair.heading_delta_deg` | Та же разница после привязки обоих датчиков к магнитному северу. |
| `g_bno_pair.orientation_delta_deg` | Наименьший пространственный поворот между системами осей датчиков, 0–180°. |
| `g_bno_pair.segment_angle_deg` | Угол между продольными осями модулей, 0–180°. Скручивание вокруг продольной оси его не меняет. Направления `−Z` пока пробные. |

## Проверка совпадения углов

1. Запустите с модулями, развернутыми по-разному. Дайте гироскопам покой
   и выполните калибровку магнитометров вдали от стали и магнитов.
2. Когда `g_bno_pair.north_ready = 1`, положите модули одной стороной вверх,
   одинаковым краем вперёд. `heading_delta_deg` и
   `orientation_delta_deg` должны быть близки к нулю в пределах точности
   датчиков. Поверните оба модуля вместе: курс должен меняться у обоих,
   а разница оставаться небольшой.
3. При `north_ready = 0` используйте `reported_heading_delta_deg` для
   наблюдения за курсами. Остальные углы пары показывают `NaN`. Если оба
   нашли север, но разница остаётся большой, проверьте, как оси микросхем
   ориентированы относительно корпусов, и магнитное окружение каждого
   модуля. Если внутренний датчик по-прежнему показывает около 39 м/с² в
   покое, это отдельно от привязки курса и мешает проверке ориентации.

NDOF привязывает курс к магнитному северу. При каждом запуске STM32 подаёт
аппаратный сброс на оба BNO, ждёт их загрузки и включает NDOF. Калибровка
начинается заново. Курсы берутся непосредственно из BNO.
Подробности: [даташит Bosch, §3.3.3 и §3.4](https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bno055-ds000.pdf#page=23).

Настройки для обоих датчиков находятся в `Core/Inc/fw_config.h`.
По умолчанию оба модуля используют встроенные генераторы и заводскую карту
осей P1 (0x24/0x00). Перед NDOF запуск проверяет настройки после сброса.
Если формат ориентации или единицы отличаются, в CONFIG записывается
UNIT_SEL = 0x80 (Android, градусы, градусы/с и м/с²).
Если чипы установлены по-разному, задайте карту осей каждого модуля по
таблице Bosch. Настройки продольных осей для угла сгиба задаются отдельно.

Чтобы вернуть рабочую прошивку на плату, завершите Debug и запустите её
обычную конфигурацию `BNO055 firmware`.
